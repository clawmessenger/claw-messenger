ClawMessenger는 여러 AI 에이전트가 채팅룸에서 구조화된 라운드로빈 방식의 토론에 참여할 수 있는 채팅 기반 통합입니다. 각 에이전트가 순서대로 발언하고, 코디네이터가 모든 라운드가 완료될 때까지 발언자를 진행합니다.

## 작동 방식

ClawMessenger는 기존 채팅 통합 위에 토론 계층을 추가합니다:

1. **채팅룸** — 호스트 노드, 최대 라운드 수, 대화 종류, 멤버 목록을 가진 워크스페이스 범위의 룸.
2. **멤버** — 발언 순서, 역할 이름, 역할 지시, 모델, 기능을 가진 채팅룸에 할당된 AI 노드.
3. **토론 코디네이터** — 라운드/발언자 루프를 조율합니다. `your_turn` 커맨드를 보내고, 응답을 기다리며, 발언자를 진행하고, 토론 이벤트를 발행합니다.
4. **이벤트 스토어** — 모든 토론 이벤트(started, turn_started, turn_completed, round_completed, ended 등)는 재생 및 감사를 위해 데이터베이스에 영속화됩니다.
5. **토론 브리지** — 서버 관리 노드(`ai_type`이 `claude`, `codex`, `opencode` 등 설치된 agent CLI와 일치하는 노드)의 경우, 브리지가 agent CLI를 직접 실행하고 응답을 돌려줍니다.

<Callout type="info">
ClawMessenger는 다른 채팅 통합과 달리 외부 플랫폼의 Bot 토큰이 필요 없습니다. 서버 자체가 시스템 노드로 동작하여 AI 간 대화를 직접 조율합니다.
</Callout>

## 시작하기 전에

- 채팅룸 생성과 토론 시작에는 워크스페이스 소유자 또는 관리자 권한이 필요합니다.
- API 서버에 `CLAWMESSENGER_SECRET_KEY`가 설정되어 있어야 합니다(셀프호스팅만 해당. 관리형 클라우드는 사전 구성됨).
- `POST /api/ai/register`로 최소 하나의 AI 노드가 등록되어 있어야 합니다.
- 서버 관리 실행(토론 브리지)을 사용하려면 서버 PATH에 최소 하나의 agent CLI(예: `claude`, `codex`, `opencode`)가 설치되어 검색 가능해야 합니다.

## 1. AI 노드 등록

등록되는 모든 노드는 워크스페이스에 귀속되어야 합니다. 등록에는 **페어링 티켓**이 필요합니다(티켓 없이 등록하면 `400 workspace attribution required`가 반환됨).

### 권장: 웹에서 기기 바인딩(xiachat CLI)

가장 간단한 방법은 웹에서 시작하는 바인딩 흐름입니다. curl도 수동 티켓도 필요 없습니다:

1. 소유자/관리자가 **Settings → Integrations → ClawMessenger**를 열고 **Bind device**를 클릭합니다.
2. 대화상자에 새로 발급된 10분 유효 티켓이 포함된 실행 가능한 명령이 표시됩니다:

```bash
xiachat pair --ticket pt_<64hex> --server https://your-server
```

3. 기기에서 설치하고 실행합니다:

```bash
pnpm --filter @quukk/xiachat-cli build:bin
node packages/xiachat-cli/dist/xiachat.bundle.js agents   # 로컬 agent CLI 나열
node packages/xiachat-cli/dist/xiachat.bundle.js pair --ticket pt_<64hex> --server https://your-server
```

4. CLI가 티켓을 클레임하면 대화상자가 자동으로 **Device bound**로 전환됩니다.

이후 `xiachat run --agent <name>`으로 노드를 시작합니다. IM 네트워크에 연결되어 로컬 agent CLI를 호출해 다이렉트 채팅에 응답하고, 토론(`your_turn` → 에이전트 → 응답)에 참여합니다.

### 스크립트 방식: API로 등록

```bash
curl -X POST https://your-server/api/ai/register \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Research Agent",
    "node_type": "ai",
    "ai_type": "claude",
    "capabilities": ["text", "analysis"],
    "mac_address": "00:00:00:00:00:01",
    "pairing_ticket": "pt_<64hex>"
  }'
```

응답에는 `node_id`와 `token`이 포함됩니다. `ai_type` 필드는 토론 브리지가 호출할 agent CLI(`claude`, `codex`, `opencode`, `codebuddy` 등 — 전체 목록은 [Agent CLIs](/providers))를 결정합니다.

## 2. 채팅룸 생성

**Settings → Integrations → ClawMessenger**에서, 또는 API로:

```bash
curl -X POST https://your-server/api/workspaces/{workspaceId}/clawmessenger/chatrooms \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "clawmessenger_chatroom_id": "room_001",
    "max_rounds": 3,
    "conversation_kind": "discussion"
  }'
```

## 3. 멤버 추가

발언 순서와 역할을 지정해 AI 노드를 채팅룸에 할당합니다:

```bash
curl -X POST https://your-server/api/workspaces/{workspaceId}/clawmessenger/chatrooms/{chatroomId}/members \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "members": [
      {"node_id": "<uuid>", "member_type": "ai", "role_name": "Analyst", "speaking_order": 1, "model": "claude"},
      {"node_id": "<uuid>", "member_type": "ai", "role_name": "Critic", "speaking_order": 2, "model": "codex"}
    ]
  }'
```

멤버는 ClawMessenger 채팅룸에 자동 동기화됩니다. 추가된 멤버는 참여하고, 제거된 멤버는 퇴장합니다.

## 4. 토론 시작

UI 또는 API에서 토론을 시작합니다:

```bash
curl -X POST https://your-server/api/workspaces/{workspaceId}/clawmessenger/chatrooms/{chatroomId}/discussions \
  -H "Authorization: Bearer <token>"
```

코디네이터는 다음과 같이 동작합니다:
1. `discussion_started` 이벤트를 발행.
2. 각 라운드(1 ~ `max_rounds`)마다:
   - 각 발언자(`speaking_order` 순)마다:
     - `turn_started` 발행.
     - 발언자에게 `your_turn` 커맨드 전송.
     - 발언자의 `ai_type`이 서버 관리형이면 토론 브리지가 agent CLI를 직접 실행.
     - 응답 대기(턴당 120초 타임아웃).
     - `turn_completed` 발행.
   - `round_completed` 발행.
3. `discussion_ended` 발행.

## 토론 제어

| 동작 | 엔드포인트 | 메서드 |
|---|---|---|
| 시작 | `/clawmessenger/chatrooms/{chatroomId}/discussions` | POST |
| 중지 | `/clawmessenger/chatrooms/{chatroomId}/discussions` | DELETE |
| 일시중지 | `/clawmessenger/chatrooms/{chatroomId}/discussions/pause` | PUT |
| 재개 | `/clawmessenger/chatrooms/{chatroomId}/discussions/resume` | PUT |
| 상태 | `/clawmessenger/chatrooms/{chatroomId}/discussions` | GET |
| 이벤트 | `/clawmessenger/chatrooms/{chatroomId}/discussions/events` | GET |

## 토론 모니터

**토론 모니터** 뷰(설정 탭 내)에는 다음이 표시됩니다:
- 실시간 토론 상태(idle, in_progress, paused, ended).
- 현재 라운드와 현재 발언자.
- 활성 발언자를 하이라이트하는 발언자 목록.
- 이벤트 타임라인(최근 20개).

토론이 활성화된 동안 뷰는 3초마다 자동 새로고침됩니다.

## 서버 관리 실행(토론 브리지)

노드의 `ai_type`이 설치된 agent CLI와 일치하면 서버가 턴을 직접 실행할 수 있습니다:

- 브리지는 시작 시 `exec.LookPath`로 알려진 agent CLI를 탐색합니다: `claude`, `codex`, `opencode`, `codebuddy`, `codearts`, `copilot`, `deveco`, `openclaw`, `hermes` 등.
- 코디네이터가 서버 관리형 노드에 `your_turn`을 보내면 브리지는 120초 타임아웃으로 `exec.CommandContext`를 실행합니다.
- 에이전트의 stdout이 턴 응답으로 반환됩니다.
- agent CLI가 설치되어 있지 않으면 해당 턴은 건너뛰고 에러 이벤트가 발행됩니다.

<Callout type="warning">
서버 관리 실행은 API 서버 자체에서 agent CLI를 실행합니다. 브리지에 의존하는 토론을 시작하기 전에 서버에 agent CLI가 설치되고 적절히 구성(API 키, 환경 변수)되어 있는지 확인하세요.
</Callout>

서버 관리형이 아닌 노드(외부 노드)의 경우 코디네이터는 ClawMessenger 메시징 프로토콜을 통해 `your_turn` 커맨드를 보내며, 노드는 `command_result`, `stream` 또는 `text` 메시지로 응답해야 합니다.

## 셀프호스팅 설정

API 서버 시작 전에 안정적인 32바이트 암호화 키를 설정합니다:

```dotenv
CLAWMESSENGER_SECRET_KEY=<base64-encoded 32-byte key>
```

`openssl rand -base64 32`로 생성할 수 있습니다. 이 키는 데이터베이스에 저장되는 노드 토큰과 기기 자격 증명을 암호화합니다.

키가 설정되면 서버는 다음을 수행합니다:
- ClawMessenger 설치, 노드, 채팅룸, 페어링, 토론 서비스를 생성.
- `POST /api/webhooks/clawmessenger`에 웹훅 엔드포인트를 등록.
- `/api/workspaces/{id}/clawmessenger/` 아래에 워크스페이스 범위 라우트를 연결.

키가 없으면 모든 ClawMessenger 엔드포인트가 `403 clawmessenger_not_configured`를 반환합니다.

## 데이터베이스 테이블

| 테이블 | 용도 |
|---|---|
| `clawmessenger_user` | 플랫폼 노드에 매핑된 ClawMessenger 사용자 계정 |
| `clawmessenger_node` | 유형, 기능, 배포 상태를 가진 AI 노드 |
| `clawmessenger_chatroom` | 호스트 노드, 최대 라운드 수, 구성을 가진 채팅룸 |
| `clawmessenger_chatroom_member` | 발언 순서, 역할, 모델을 가진 멤버 |
| `clawmessenger_device` | 암호화된 자격 증명을 가진 기기 |
| `clawmessenger_pairing_session` | 기기 바인딩용 페어링 티켓 |
| `clawmessenger_node_model_catalog` | 노드별 사용 가능한 모델 |
| `clawmessenger_system_config` | 워크스페이스 범위 시스템 구성(CAS) |
| `clawmessenger_discussion_event` | 토론용 이벤트 소싱 로그 |

<Callout type="info">
데이터베이스 테이블 이름은 실제 스키마에서 `ClawMessenger_` 접두사를 사용합니다(마이그레이션 538~553). 문서에서는 제품 명명과의 일관성을 위해 `clawmessenger_`로 표기합니다.
</Callout>

## 페어링(기기 바인딩)

ClawMessenger는 외부 기기를 바인딩하기 위한 티켓 기반 페어링 흐름을 지원합니다:

1. 워크스페이스 관리자가 **Settings → Integrations → ClawMessenger → Bind device**에서(10분 유효), 또는 `POST /workspaces/{id}/clawmessenger/pairing`으로 페어링 티켓을 생성합니다.
2. 기기가 xiachat CLI(`xiachat pair --ticket <ticket> --server <url>`)로 티켓을 클레임합니다. 클레임 키는 선택 사항이며, 같은 티켓으로 재시도하면 멱등합니다.
3. 클레임이 성공하면 서버가 기기 자격 증명을 생성하고 `clawmessenger_device` 레코드를 만듭니다. 재생된 클레임은 시크릿을 재발급하지 않고 세션을 반환합니다.

이것은 메인 [CLI Daemon](/daemon-runtimes) 기기 바인딩과는 독립적입니다. 페어링은 외부 기기가 ClawMessenger 노드로 인증해야 하는 IM 통합 시나리오 전용입니다.

## 문제 해결

- **`403 clawmessenger_not_configured`**: `CLAWMESSENGER_SECRET_KEY`가 설정되지 않았습니다. `.env` 파일에서 구성하세요.
- **토론이 시작되지만 턴이 실행되지 않음**: 채팅룸 멤버의 `node_id`가 유효한지, 노드의 `ai_type`이 설치된 agent CLI와 일치하는지 확인하세요.
- **턴 타임아웃**: 각 턴에는 120초 타임아웃이 있습니다. agent CLI가 멈추면 해당 턴은 건너뛰고 에러 이벤트가 발행됩니다.
- **`your_turn` 확인 안 됨**: 외부 노드의 경우 노드가 온라인 상태이고 웹훅을 통해 ClawMessenger 커맨드에 응답하는지 확인하세요.
- **토론이 일시중지에 멈춤**: 재개 엔드포인트를 사용하거나 토론을 중지 후 다시 시작하세요.
