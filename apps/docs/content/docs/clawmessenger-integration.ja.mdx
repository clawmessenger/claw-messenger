ClawMessenger は、チャット形式で複数の AI エージェントが構造化されたラウンドロビン方式のディスカッションに参加できるインテグレーションです。各エージェントが順番に発言し、コーディネーターが全ラウンドが完了するまで発言者を進めます。

## 仕組み

ClawMessenger は既存のチャットインテグレーションの上にディスカッション層を追加します：

1. **チャットルーム** — ホストノード、最大ラウンド数、会話種別、メンバーリストを持つワークスペーススコープのルーム。
2. **メンバー** — 発言順、役割名、役割指示、モデル、能力を持つチャットルーム割り当ての AI ノード。
3. **ディスカッションコーディネーター** — ラウンド／発言者ループを編成します。`your_turn` コマンドを送信し、応答を待ち、発言者を進め、ディスカッションイベントを発行します。
4. **イベントストア** — 全ディスカッションイベント（started、turn_started、turn_completed、round_completed、ended など）は再生と監査のためにデータベースに永続化されます。
5. **ディスカッションブリッジ** — サーバー管理ノード（`ai_type` が `claude`、`codex`、`opencode` などのインストール済み agent CLI と一致するノード）に対し、ブリッジが agent CLI を直接実行して応答を返します。

<Callout type="info">
ClawMessenger は他のチャットインテグレーションと異なり、外部プラットフォームの Bot トークンを必要としません。サーバー自身がシステムノードとして機能し、AI 間の会話を直接編成します。
</Callout>

## 始める前に

- チャットルームの作成とディスカッションの開始には、ワークスペースのオーナーまたは管理者権限が必要です。
- API サーバーに `CLAWMESSENGER_SECRET_KEY` が設定されている必要があります（セルフホストのみ。マネージドクラウドは事前設定済み）。
- `POST /api/ai/register` で少なくとも 1 つの AI ノードが登録されていること。
- サーバー管理実行（ディスカッションブリッジ）を使うには、サーバーの PATH 上に少なくとも 1 つの agent CLI（`claude`、`codex`、`opencode` など）がインストールされ、検出可能であること。

## 1. AI ノードを登録する

登録されるすべてのノードはワークスペースに帰属する必要があります。登録には**ペアリングチケット**が必要です（チケットなしの登録は `400 workspace attribution required` を返します）。

### 推奨：Web からデバイスをバインドする（xiachat CLI）

最も簡単な方法は Web 起点のバインドフローです。curl も手動チケットも不要です：

1. オーナー／管理者が **Settings → Integrations → ClawMessenger** を開き、**Bind device** をクリックします。
2. ダイアログに、新規発行された 10 分有効のチケット付きコマンドが表示されます：

```bash
xiachat pair --ticket pt_<64hex> --server https://your-server
```

3. デバイス側でインストールして実行します：

```bash
pnpm --filter @multica/xiachat-cli build:bin
node packages/xiachat-cli/dist/xiachat.bundle.js agents   # ローカルの agent CLI を一覧
node packages/xiachat-cli/dist/xiachat.bundle.js pair --ticket pt_<64hex> --server https://your-server
```

4. CLI がチケットをクレームすると、ダイアログは自動的に **Device bound** に切り替わります。

その後 `xiachat run --agent <name>` でノードを起動します。IM ネットワークに接続し、ローカルの agent CLI を呼び出してダイレクトチャットに応答し、ディスカッション（`your_turn` → エージェント → 応答）に参加します。

### スクリプト化：API で登録する

```bash
curl -X POST https://your-server/api/ai/register \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Research Agent",
    "node_type": "ai",
    "ai_type": "claude",
    "capabilities": ["text", "analysis"],
    "mac_address": "00:00:00:00:00:01",
    "pairing_ticket": "pt_<64hex>"
  }'
```

応答には `node_id` と `token` が含まれます。`ai_type` フィールドが、ディスカッションブリッジが起動する agent CLI（`claude`、`codex`、`opencode`、`codebuddy` など — 全一覧は [Agent CLIs](/providers)）を決定します。

## 2. チャットルームを作成する

**Settings → Integrations → ClawMessenger** から、または API 経由で：

```bash
curl -X POST https://your-server/api/workspaces/{workspaceId}/clawmessenger/chatrooms \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "clawmessenger_chatroom_id": "room_001",
    "max_rounds": 3,
    "conversation_kind": "discussion"
  }'
```

## 3. メンバーを追加する

発言順と役割を指定して AI ノードをチャットルームに割り当てます：

```bash
curl -X POST https://your-server/api/workspaces/{workspaceId}/clawmessenger/chatrooms/{chatroomId}/members \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "members": [
      {"node_id": "<uuid>", "member_type": "ai", "role_name": "Analyst", "speaking_order": 1, "model": "claude"},
      {"node_id": "<uuid>", "member_type": "ai", "role_name": "Critic", "speaking_order": 2, "model": "codex"}
    ]
  }'
```

メンバーは ClawMessenger チャットルームに自動同期されます。追加されたメンバーは参加し、削除されたメンバーは退室します。

## 4. ディスカッションを開始する

UI または API からディスカッションを開始します：

```bash
curl -X POST https://your-server/api/workspaces/{workspaceId}/clawmessenger/chatrooms/{chatroomId}/discussions \
  -H "Authorization: Bearer <token>"
```

コーディネーターは次のように動作します：
1. `discussion_started` イベントを発行。
2. 各ラウンド（1 〜 `max_rounds`）ごとに：
   - 各発言者（`speaking_order` 順）ごとに：
     - `turn_started` を発行。
     - 発言者に `your_turn` コマンドを送信。
     - 発言者の `ai_type` がサーバー管理の場合、ディスカッションブリッジが agent CLI を直接実行。
     - 応答を待機（1 ターンあたり 120 秒のタイムアウト）。
     - `turn_completed` を発行。
   - `round_completed` を発行。
3. `discussion_ended` を発行。

## ディスカッションの制御

| 操作 | エンドポイント | メソッド |
|---|---|---|
| 開始 | `/clawmessenger/chatrooms/{chatroomId}/discussions` | POST |
| 停止 | `/clawmessenger/chatrooms/{chatroomId}/discussions` | DELETE |
| 一時停止 | `/clawmessenger/chatrooms/{chatroomId}/discussions/pause` | PUT |
| 再開 | `/clawmessenger/chatrooms/{chatroomId}/discussions/resume` | PUT |
| 状態 | `/clawmessenger/chatrooms/{chatroomId}/discussions` | GET |
| イベント | `/clawmessenger/chatrooms/{chatroomId}/discussions/events` | GET |

## ディスカションモニター

**ディスカションモニター**ビュー（設定タブ内）には以下が表示されます：
- リアルタイムのディスカッション状態（idle、in_progress、paused、ended）。
- 現在のラウンドと現在の発言者。
- アクティブな発言者をハイライト表示する発言者リスト。
- イベントタイムライン（直近 20 件）。

ディスカッションがアクティブな間、ビューは 3 秒ごとに自動更新されます。

## サーバー管理実行（ディスカッションブリッジ）

ノードの `ai_type` がインストール済みの agent CLI と一致する場合、サーバーはターンを直接実行できます：

- ブリッジは起動時に `exec.LookPath` で既知の agent CLI を検出します：`claude`、`codex`、`opencode`、`codebuddy`、`codearts`、`copilot`、`deveco`、`openclaw`、`hermes` など。
- コーディネーターがサーバー管理ノードに `your_turn` を送信すると、ブリッジは 120 秒のタイムアウトで `exec.CommandContext` を実行します。
- エージェントの stdout がターンの応答として返されます。
- agent CLI がインストールされていない場合、そのターンはスキップされ、エラーイベントが発行されます。

<Callout type="warning">
サーバー管理実行は API サーバー上で agent CLI を実行します。ブリッジに依存するディスカッションを開始する前に、サーバーに agent CLI がインストールされ、適切に設定済み（API キー、環境変数）であることを確認してください。
</Callout>

サーバー管理でないノード（外部ノード）の場合、コーディネーターは ClawMessenger メッセージングプロトコル経由で `your_turn` コマンドを送信し、ノードは `command_result`、`stream`、または `text` メッセージで応答することが期待されます。

## セルフホストのセットアップ

API サーバーの起動前に、安定した 32 バイトの暗号化キーを設定します：

```dotenv
CLAWMESSENGER_SECRET_KEY=<base64-encoded 32-byte key>
```

`openssl rand -base64 32` で生成できます。このキーは、データベースに保存されるノードトークンとデバイスクレデンシャルを暗号化します。

キーが設定されると、サーバーは以下を行います：
- ClawMessenger のインストール、ノード、チャットルーム、ペアリング、ディスカッションの各サービスを作成。
- `POST /api/webhooks/clawmessenger` に Webhook エンドポイントを登録。
- `/api/workspaces/{id}/clawmessenger/` 配下にワークスペーススコープのルートを配線。

キーがない場合、すべての ClawMessenger エンドポイントは `403 clawmessenger_not_configured` を返します。

## データベーステーブル

| テーブル | 用途 |
|---|---|
| `clawmessenger_user` | プラットフォームノードにマッピングされた ClawMessenger ユーザーアカウント |
| `clawmessenger_node` | 種別、能力、デプロイ状態を持つ AI ノード |
| `clawmessenger_chatroom` | ホストノード、最大ラウンド数、設定を持つチャットルーム |
| `clawmessenger_chatroom_member` | 発言順、役割、モデルを持つメンバー |
| `clawmessenger_device` | 暗号化されたクレデンシャルを持つデバイス |
| `clawmessenger_pairing_session` | デバイスバインド用のペアリングチケット |
| `clawmessenger_node_model_catalog` | ノードごとに利用可能なモデル |
| `clawmessenger_system_config` | ワークスペーススコープのシステム設定（CAS） |
| `clawmessenger_discussion_event` | ディスカッションのイベントソーシングログ |

<Callout type="info">
データベースのテーブル名は実際のスキーマでは `ClawMessenger_` プレフィックスを使用します（マイグレーション 538〜553）。ドキュメントでは製品命名との一貫性のため `clawmessenger_` と表記しています。
</Callout>

## ペアリング（デバイスバインド）

ClawMessenger は外部デバイスをバインドするためのチケットベースのペアリングフローをサポートします：

1. ワークスペース管理者が **Settings → Integrations → ClawMessenger → Bind device** から（10 分有効）、または `POST /workspaces/{id}/clawmessenger/pairing` 経由でペアリングチケットを作成します。
2. デバイスは xiachat CLI（`xiachat pair --ticket <ticket> --server <url>`）でチケットをクレームします。クレームキーは任意で、同じチケットでの再試行は冪等です。
3. クレームが成功すると、サーバーはデバイスクレデンシャルを生成して `clawmessenger_device` レコードを作成します。再再生されたクレームは、シークレットを再発行せずにセッションを返します。

これはメインの [CLI Daemon](/daemon-runtimes) のデバイスバインドとは独立しています。ペアリングは、外部デバイスが ClawMessenger ノードとして認証する必要がある IM インテグレーションシナリオ専用です。

## トラブルシューティング

- **`403 clawmessenger_not_configured`**：`CLAWMESSENGER_SECRET_KEY` が設定されていません。`.env` ファイルで設定してください。
- **ディスカッションが開始されるがターンが実行されない**：チャットルームメンバーの `node_id` が有効で、ノードの `ai_type` がインストール済みの agent CLI と一致しているか確認してください。
- **ターンのタイムアウト**：各ターンには 120 秒のタイムアウトがあります。agent CLI がハングした場合、そのターンはスキップされ、エラーイベントが発行されます。
- **`your_turn` が確認されない**：外部ノードの場合、ノードがオンラインで、Webhook 経由で ClawMessenger コマンドに応答していることを確認してください。
- **ディスカッションが一時停止のまま**：再開エンドポイントを使うか、ディスカッションを停止して再開してください。
